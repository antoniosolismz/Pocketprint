# Pocket Print — companion for the "Funny Print" / Dolewa mini thermal printer

A replacement for the vendor app `com.lailaixiong.funnyprint` (2.8.1). It speaks the
printer's Bluetooth protocol directly, prints text, photographs and **labels with QR codes
and barcodes**, and talks to nothing else: no account, no cloud, no analytics, no
permissions beyond Bluetooth. Installed, it works with the network switched off.

```
PROTOCOL.md          byte-level spec, with the evidence anchor for every claim
py/funnyprint/       reference library (protocol, raster, BLE client, CLI)
py/tests/            self-contained test suite + vector generator
web/index.html       the app: single page, Web Bluetooth, installable offline
web/funnyprint.js    protocol + transport + the raster pipeline
web/codes.js         QR and Code 128, producing print-ready 1-bit bitmaps
web/label.js         label layout planning (pure geometry, so layout bugs are testable)
web/vendor/          vendored dependencies (QR encoder, Code 128 pattern table)
web/icons/           app icons, generated by tools/make-icons.py
web/sw.js            service worker: keeps the app working offline
web/tests/           5 suites + an independent decode verifier
tools/               generators for the vendored table and the icons
```

## The app (recommended)

**Live at https://print.otelo2.com** — open it in **Chrome or Edge** (Android, or any
Chromium desktop; Firefox has no Web Bluetooth). It installs to the home screen as a real
app and then runs with no network at all.

Four modes:

- **Text** — wrapping, three sizes, three faces, left/centre/right.
- **Image** — rotate, auto-levels, brightness, contrast, sharpen, four halftone modes, and
  Photo / Document / Sticker presets.
- **Label** — a title, a subtitle, an optional QR code or Code 128 barcode, a border, and a
  tear-off gap. The preview shows the label's length in millimetres, so you know what it
  costs in paper before you print it.
- **Batch** — paste a list, one label per line (`Title<TAB>subtitle` or `Title | subtitle`),
  copies of each, optional numbering, and cut guides between labels. The whole batch prints
  as one continuous sheet.

Plus: live progress with packet count and ETA, the printer's own battery and paper status in
the header (it broadcasts it every two seconds; this used to sit unread in the log), a
local reprint history, and a copyable log for when something misbehaves.

### How the settings are scoped

Two style scopes, deliberately:

- **Text** — face, size and alignment for text jobs only.
- **Label** — face, alignment, title and subtitle sizes, border, cut guide and tear-off. This
  is **one object shared by the Label and Batch tabs**, because a batch is the label template
  applied to a list; editing it from either tab changes both. Two separate label styles would
  be the same confusion in the other direction.

Everything else belongs to the printer or the paper rather than to the content, so it stays
global: density and threshold (ink), width and copies (paper).

The page is a set of collapsible groups, and **each collapsed summary shows its current
values** — `Print quality — density 4 · threshold 128`. Collapsing hides the controls, never
the state, so you can read the whole configuration without opening anything. The preview is
sticky while you edit, and the printer group folds itself away once connected.

The **threshold** applies to every mode, not just images: it decides where the line between
ink and paper falls, so raising it makes photographs darker *and* text bolder. (The old copy
said "lower = darker", which was backwards.)

Everything is client-side: `web/` is a directory of static files, no build step, no backend.
Web Bluetooth needs a secure origin from a phone, which is why it is served over HTTPS.

## Where it runs

| | |
|---|---|
| LXC | `136` `pocketprint` on `virtual`, **192.168.0.221** (services block, `onboot 1`) |
| Web server | nginx, static root `/var/www/pocketprint`, site `pocketprint` |
| Public name | `print.otelo2.com` → Cloudflare tunnel `virtual` → `http://192.168.0.221:80` |
| Monitoring | Wazuh agent `024 pocketprint`; `homelab_health.sh` checks both the public name and the LAN origin; Glance "Services" tile |
| Deploy | `./deploy.sh` — packages `web/`, pushes, then verifies sha256 on the LAN origin **and** through the tunnel |

Updating the app is `./deploy.sh` (add `--dry-run` to see the digests without pushing).
There is deliberately **no LAN friendly name** for this one: the internal proxy publishes
`*.home.arpa` over plain HTTP, and Web Bluetooth does not run outside a secure context —
a `http://pocketprint.home.arpa` route would load a page that cannot print. The public
HTTPS name works from inside the house too.

## Desktop CLI

```bash
python3 py/funnyprint/cli.py scan                  # list nearby BLE devices
python3 py/funnyprint/cli.py info   --name LX-D02  # connect, report MAC/auth/battery
python3 py/funnyprint/cli.py test   --name LX-D02  # print the calibration sheet
python3 py/funnyprint/cli.py text   "hello" --name LX-D02
python3 py/funnyprint/cli.py image  photo.png --density 4 --threshold 120 --no-dither
python3 py/funnyprint/cli.py feed   --rows 6       # advance paper (prints blank rows)
python3 py/funnyprint/cli.py dry-run --text "hello" # no Bluetooth: dump every frame
```

Live printing needs `pip install --user bleak`. `--dry-run` and the whole test suite work
on the standard library plus Pillow.

## Calibration

The printer does not advertise its dot width, and the vendor app doesn't hardcode one
either (it passes a width down from JavaScript per template). So:

1. Print the calibration sheet at 384 (default).
2. If the right-hand frame edge is missing or the image is squeezed, try 400 (50 mm
   label models) or 576 (80 mm models); narrow label models take 240 or 200.

Ticks on the sheet are 8 dots apart, labelled every 64 dots. If the frame lands exactly
on both edges at 384, you are set.

## Why every script is stamped, and the worker revalidates

Cloudflare rewrites responses to `max-age=14400` — its own four-hour TTL — regardless of the
origin's `Cache-Control: no-cache`, and the API token for this zone cannot purge. So:

- **every** local script URL carries `?v=<build hash>`, written by `deploy.sh`. A changed build
  means a changed URL, so the page and its libraries always arrive as a matched set and no cache
  can mix them;
- the service worker fetches with `cache: 'no-cache'`, so an installed app revalidates instead
  of trusting that TTL, and its cache name is stamped per build so stale caches get dropped;
- the page checks at startup for the APIs it needs and **says so** when one is missing.

That combination exists because of a real failure worth remembering: a new page ran against a
four-hour-old `label.js`, and the label and batch previews stopped updating *with no error at
all* — the render path threw, nothing repainted, and there was nothing on screen to explain it.
Note the shape of it: text and image were fine, because they never touched the function that had
been added. A silent freeze that follows a seam between two code paths is a caching or
version-mismatch symptom, not a logic bug.

## What the paper caught

Three defects that no test could have found before printing, in the order the paper revealed them:

1. **Clipped text.** "…a lovely rack" instead of "…a lovely racket." Each line was drawn at a
   fixed size and never measured against the page, so everything past ~31 characters vanished
   mid-word. Text is now wrapped against the real printable width.
2. **A photo printed as black mush.** A night photograph came out as dense grain with the
   shadows crushed together. A dark source plus no tone curve plus a 1-bit head leaves shadow
   detail nowhere to go, and no amount of thresholding recovers what the histogram never had.
   Hence auto-levels, brightness and contrast, applied *before* halftoning.
3. **Half of a batch printed, with the cut guides in the right places.** The page placed text
   itself, at `plan.y + baseline` — where `baseline` already included `plan.y`. The first label
   on a sheet sits at y = 0, so a single label looked perfect; labels 2, 3 and 4 slid down by
   one label-height each, and half of a four-label batch printed off the bottom of the paper.
   The guides were computed absolutely and were correct, which is what made the symptom so
   confusing.

The fix for (3) was structural, not local: **all placement arithmetic moved into
`label.js#absoluteLayout`**, where it is tested, and the page draws what it is handed and never
adds an offset of its own. `wiring.mjs` now enforces that the page contains no layout maths, so
this class of bug cannot come back quietly.

## What was verified, and how

Six test suites, ~334 checks. Run them all:

```bash
for t in conformance codes render wiring; do node web/tests/$t.mjs; done
python3 py/tests/test_all.py
python3 web/tests/verify-codes.py          # needs opencv + python-barcode
```

- `py/tests/test_all.py` — 87 checks: CRC/auth derivation, frame layouts, the service UUID,
  notification parsing, raster semantics, flow control (hold, cooldown, lost packet) and a
  **complete print job driven against a mock printer**.
- `web/tests/conformance.mjs` — 67 checks: the JavaScript core is asserted **byte-identical
  to the Python reference** (CRC, auth, frames, raster vectors), the wire frames are pinned
  against the documented bytes of an independent implementation, and a full job runs through
  the real `PrinterLink` over a fake printer — including a hold, a rewind, and the adaptive
  pacing.
- `web/tests/codes.mjs` — 49 checks: Code 128 is asserted **byte-for-byte against
  python-barcode** for fifteen payloads (single digits, odd digit runs, punctuation that
  forces a charset switch), plus QR structure, integer module snapping and geometry guards.
- `web/tests/render.mjs` — 74 checks: each halftone's character (Atkinson keeps pure black
  and pure white; Bayer is periodic with period 8), sharpen, rotation, the **label planner's
  geometry** — blocks do not overlap, nothing exceeds 384 dots, a long title wraps rather than
  being clipped, an impossible QR degrades to a warning instead of a crash — and
  **absolute placement**, which is the batch bug in §"What the paper caught": on a multi-label
  sheet every label's text must sit inside its own band.
- `web/tests/wiring.mjs` — 59 checks: the page is loaded the way a *browser* would
  (a `vm` sandbox with no `module`, scripts in tag order), every `$('id')` is checked against
  the markup, the service worker is checked to pre-cache the whole shell, the page is checked
  to contain **no off-origin URLs and no fetch/XHR/WebSocket calls at all**, and the page is
  checked to do **no layout arithmetic of its own** (that rule is what the batch bug broke).
  This suite exists because four wiring bugs got past every other suite.
- `web/tests/verify-codes.py` — the independent half: it renders the bitmaps the app would
  send, decodes the QRs with **OpenCV's detector**, and compares Code 128 against
  **python-barcode**. 10/10 QR bitmaps decode, including the ones inside a composed label.

**The protocol has been cross-checked against hardware.** The frame layouts, handshake,
auth derivation and raster packing were verified against
[cicloid/printable](https://github.com/cicloid/printable) — an independent,
hardware-validated reimplementation of this same printer family. That cross-check found two
bugs in this project's first version (the GATT service is `0xFFE6`, and the raster packet
carries a packet *index* where we were writing a byte offset). `PROTOCOL.md` §9 records
both, because the second one would have printed one good packet and then garbage.

**Confirmed on an actual LX-D02 (2026-10-14).** Test page, text and a 341-packet photo all
printed on hardware. The session log confirms the handshake for real: the device answered
`5A 01` with its MAC, the `5A 0A` reply payload **matched the vendor app's low-CRC check**
(the one step in this protocol where a wrong guess would have been a locked door rather than
a garbled page), auth returned ok, and the raster framed at packet indices `0x0000`,
`0x0001`, … One more thing the paper confirmed: **the first text renderer clipped long lines
mid-word** — "…a lovely rack" instead of "…a lovely racket." — because each line was drawn
at a fixed size and never measured against the page. Text is now wrapped against the real
printable width, with the measurement tested in the browser.

The modes and the label composer have **not** been through the printer yet: they are
verified by the suites above and by rendering them through the app's own pipeline in a real
browser (the QR drawn in the preview was compared dot-for-dot against the QR matrix —
113,520 dots, zero mismatches). Paper is still the final word.

**What is still unknown** is small: an undocumented 12-byte `0x0C` frame the printer emitted
once (recorded, not acted on — see `PROTOCOL.md` §4), and whether the 60 ms pacing cap is
the right ceiling for the longest jobs.

## Vendored dependencies, and why

- `web/vendor/qrcode.js` — [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator)
  1.4.4, MIT, unmodified (licence header intact). Reed–Solomon and QR masking are not things
  to reimplement at midnight, and loading it from a CDN would break the no-network promise.
  Verified by decoding its output with an independent decoder.
- `web/vendor/code128-table.js` — the 106 ISO/IEC 15417 symbol patterns, **generated** by
  `tools/make-code128-table.py` from python-barcode rather than transcribed by hand (hand
  transcription is how you ship a barcode that scans as garbage), then spot-checked against
  the published values in the test suite.

The render pipeline (tone, sharpening, the four halftone modes) lives in JavaScript only —
it is the product, not the protocol. The Python side remains the byte-level reference for
framing, auth and raster packing, and the conformance suite pins the two together there.

If it misbehaves, the ground truth is an HCI snoop log: Developer options → "Enable
Bluetooth HCI snoop log", print once with the vendor app, pull `/sdcard/btsnoop_hci.log`,
open it in Wireshark, and diff it against `cli.py dry-run`.

## Safety notes

- The printer is one-way for our purposes: the host writes when asked, and only 96-byte
  raster slices leave the machine. Nothing about you is transmitted.
- The vendor app's own analysis (permissions, SDKs, endpoints, and the cloud image
  uploads) is in the project notes; printing never needed any of it.
